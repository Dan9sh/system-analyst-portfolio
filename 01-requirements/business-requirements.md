## 2 Границы
**Входит**
- Шаблоны уведомлений
- Каналы push (FCM для Android, APNs для iOS) и СМС (SMSC.ru, HTTP/REST).
- Очередь сообщений как транспорт событий-триггеров
- Категории уведомлений: платежные напоминания(информационные)
- Согласия на канал, тихие часы, приоритеты доставки, фолбэк (перенаправление при недоставки) push на СМС, частотный лимит
**Не входит**
- E-mail - нет интеграции и согласий, отдельный бэклог.
- Мессенджеры (Telegram, WhatsApp) - отдельный бэклог.
- Голосовые звонки - не канал уведомлений.
- Рекламные рассылки и промо
- Категории уведомлений: сервисные/безопасность, маркетинговые

## 3 Бизнес правила

| ID   | Правило                                                                                           | Источник    |
| ---- | ------------------------------------------------------------------------------------------------- | ----------- |
| BR-1 | Если push не доставлен за 50 секунд - выполняется фолбэк на СМС Не более 1 уведомления в 10 минут | Бизнес      |
| BR-2 | Повторное событие с тем же идентификатором не порождает второе уведомление (дедупликация)         | Архитектура |


# 4 Функциональные требования

| ID   | Требование                                                                                              | Категория     | Связь            | Приоритет |
| ---- | ------------------------------------------------------------------------------------------------------- | ------------- | ---------------- | --------- |
| FR-1 | Система должна принимать события-триггеры из внешних систем (биллинг, антифрод, маркетинг) через Kafka. | Транспорт     | G1, G2, G3       | Must      |
| FR-2 | Система должна отправлять push через FCM (Android) и APNs (iOS).                                        | Доставка      | UR-1, UR-2, UR-3 | Must      |
| FR-3 | Система должна отправлять СМС через SMSC.ru по HTTP/REST API.                                           | Доставка      | BR-1             | Must      |
| FR-4 | Система должна фиксировать статус каждого уведомления: отправлено, доставлено, ошибка.                  | Учет          | BR-1             | Must      |
| FR-5 | Система выполняет дедупликацию повторных событий по идентификатору.                                     | Маршрутизация | BR-2             | Should    |

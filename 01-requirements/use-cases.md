| Поле | Значение |
|------|----------|
| ID / название | UC-1 / Отправка напоминания о дате платежа |
| Актор | Система-источник события (биллинг кредитных карт) |
| Цель | Доставить клиенту напоминание о предстоящем платеже до наступления даты |
| Предусловие | • Клиент существует и имеет активную кредитную карту с непогашенной задолженностью.<br>• Известны контакты клиента: токен устройства или подтвержденный номер телефона.<br>• Шаблон текста напоминания утвержден и доступен системе. |
| Триггер | В Kafka поступило событие о приближении даты платежа |
| Основной сценарий | 1. Система принимает событие из Kafka и проверяет его на дубль по ключу дедупликации.<br>2. Определяет категорию уведомления<br>3. Формирует текст по шаблону, подставляя дату и сумму платежа.<br>4. Отправляет push через FCM или APNs.<br>5. Получает подтверждение доставки и фиксирует статус доставлено. |
| Альтернативы | A1. Категория критичная - проверка согласия на рекламу и тихих часов пропускается, отправка идет сразу (BR-3).<br>A2. У клиента отключены push, но есть подтвержденный телефон - напоминание сразу отправляется по СМС, без попытки push. |
| Исключения | E1. Push не доставлен за 30 секунд - фолбэк на СМС через SMSC.ru, статус фолбэк.<br>E2. Токен устройства невалиден - токен помечается невалидным, сразу фолбэк на СМС, инициируется обновление токена. Отправляется ошибка<br>E3. SMSC.ru недоступен - событие остается в очереди, ретрай, алерт; при исчерпании ретраев статус ошибка. Отправляется ошибка<br>E4. Нет ни валидного токена, ни телефона - статус недоставлено с причиной. Отправляется ошибка<br>E5. Дубль события из Kafka - второе уведомление не отправляется, дубль фиксируется в логе. Отправляется ошибка |
| Постусловие | Клиент получил напоминание по одному из каналов, либо зафиксирована причина недоставки.<br>Статус доставки записан и доступен в аналитике (FR-7). |
| Связанные story / правила | US-1; BR-3 (критичные отправляются всегда), BR-4 (фолбэк на СМС только для критичных); FR-6, FR-7 |
